# 从一个满意镜头，积累到可复用的方法

工程模板、动画组件和 Skill 承担不同工作：工程保存一条片子的结构；组件保存一个可调整的动作；Skill 告诉助手什么时候、怎样使用已有方法和文件。

Skill 是外部说明与资源组织方式，不是训练模型权重。只保存一句提示词，不能保证下次得到同样的画面。

## 入门先保存什么

做完聊天练习后，填写 [镜头说明](../templates/reusable-shot.md)，与代码一起保存：

- 它解决什么表达问题，实际画面是什么。
- 哪些参数可以改，哪些改动需要重新布局。
- 使用哪些工具、依赖、字体和素材，如何预览和导出。
- 从什么时候开始出现、什么时候结束，怎样接到整片时间线上。
- 实际成功导出的版本、预览，以及仍存在的限制。

不把私人聊天、凭证或无法再分发的素材带进公共示例。给公开练习换成中性内容，并保留必要来源。

## 什么时候再提炼 Skill

当同一方法在另一个主题中也运行成功，且确实节省了重复工作，就有了提炼依据。可整理成这样的材料：

```text
一个动作的方法包/
  使用说明.md       # 适用场景、输入输出、操作和限制
  example/          # 可运行示例、锁文件和相对路径素材
  preview/          # 小预览及其对应版本
  sources.md        # 来源、许可、必需的外部资源
```

需要让具体 AI 客户端自动发现时，再按该客户端当前 Skill 规范编写入口文件，并从干净的目录做一次完整调用验证。安装位置和入口格式留给所用客户端的官方说明，普通项目资料不必全部变成全局 Skill。

有效的指令要能回答“用哪个已有文件、改哪些地方、怎样验证结果”。避免把一次作品的配色、时长、情绪和字幕风格写成所有视频的硬规则。

wise-motion 提供了“动作目录＋代码＋调用入口”的参考；ai-workflow-prompts 提供了“制作步骤＋修订规则”的参考。我们可以分别学习它们，逐步沉淀自己的稳定路径。
