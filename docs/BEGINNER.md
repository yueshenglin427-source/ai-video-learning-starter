# 入门：把一个短镜头改成自己的

这次只做一件事：让聊天消息和人物动作一起表达“把模糊要求变成具体修改”。先完成无声练习，再考虑配音与音乐。

## 1. 先看见结果

下载并解压仓库，用浏览器打开 `examples/chat-motion/demo.html`。点播放，再把时间条分别拖到 1、4、8 秒。观察消息怎样出现、旧消息怎样上移、人物何时停下来。

这个例子的画面由时间控制。它能回退和定位，适合反复修改一个镜头；它目前还不是 MP4 文件。

## 2. 让 AI 改一份副本

把本机解压路径告诉能读写文件的 AI 工具，使用下面这段练习要求：

```text
请先阅读 examples/chat-motion/README.md 及示例源码。
把 examples/chat-motion 复制为 examples/my-first-shot，在副本里修改。
把五条聊天依次改为：
“这段我没看懂。”
“哪里跟不上？”
“两个对象同时动了。”
“先动一个，另一个等一下。”
“这次看清了。”
调整消息出现时间，保持总长10秒，让人物停下来的动作和最后的确认衔接。
沿用现有组件与播放控件，保留原始示例。
完成后告诉我打开哪个文件，以及改动的消息和时间在哪里。
```

打开副本，实际播放。重点看第三、四条是否有足够的阅读时间，而不是要求每条平均分配两秒。文字过长时，先缩短句子，或合理增加片长；不要只把字缩小。

## 3. 做一次有依据的修订

记录具体时间和问题。例如：“第4秒第三条刚出现，第四条就把它顶走了，我还没读完。”让 AI 调整这两条之间的间隔，同时检查最后一句是否仍能读完。

可用的反馈包含：发生在哪里、观众跟不上什么、希望先看到哪个动作。调整后再从前一条消息开始播放，检查衔接。

## 4. 导出一条真正的视频

按 [QUICKSTART](../QUICKSTART.md) 建立独立工程。熟悉 React 可以选择 Remotion；想沿用网页组织方式可以从 HyperFrames 路线开始。首次只接一种框架。

把修改后的副本和它的 README 交给助手，要求：

```text
将这个10秒网页镜头接入我选择的视频框架，输出1920×1080、30fps的无声MP4。
保留聊天和人物的相对位置，按目标画幅重新检查布局。
使用整片时间驱动画面；镜头局部时间传给 seek(seconds)，不要叠加自动播放计时器。
复制所需源码和样式到新工程，用相对路径引用。
记录实际框架版本、预览和导出命令，并保留依赖锁文件。
先导出一段包含消息切换与人物动作的连续样稿，查看后修正问题，再导出完整10秒。
```

浏览器里能播放不等于视频导出成功。打开最终 MP4，核对时长、文字、开头结尾和动作；不要只看终端的成功提示。

## 5. 把这次成功留下来

保留源文件、锁文件、命令和最终视频，填写 [镜头说明](../templates/reusable-shot.md)。下次换主题时，先从这个工程改内容，再判断是否需要新动作。

入门完成的标志是：你能找到要改的内容，能指出某一秒的问题，改完还能再次导出。复杂三维、自动口播剪辑和完整 Skill 封装可以稍后再学。
